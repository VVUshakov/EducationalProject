# EducationalProject

Краткий итог:

Что важно понять:
Наследование - все программы наследуются от BaseService (как дети от родителей)
Абстрактные классы - BaseService как шаблон, который говорит "все программы должны иметь Name и Run()"
Полиморфизм - MenuManager работает с любыми программами через BaseService, не зная их конкретного типа
Инкапсуляция - каждый класс скрывает свои внутренние детали (private методы)
Модульность - каждая программа в отдельном файле, каждая ответственность в отдельном классе

Ключевые концепции:
static классы - можно использовать без создания объекта (ConsoleHelper, InputValidator)
const - константы (неизменяемые значения)
foreach - перебор элементов коллекции
switch expression - современный способ выбора в зависимости от значения
string interpolation - $"Текст {переменная}" для вставки переменных в строки
массивы - string[] - набор элементов одного типа
списки - List<string> - динамический массив

--------------------------------------------------------------
Анализ SOLID:
1. Single Responsibility (Единая ответственность)
Каждый класс делает что-то одно:
Calculator - только вычисления
BinaryConverter - только конвертация чисел
ConsoleHelper - только вывод в консоль
InputValidator - только проверка ввода

2. Open/Closed (Открытость/Закрытость)
Можно добавлять новые программы, не меняя старый код:
Создаем новый класс, наследуем от BaseService
Реализуем Name и Run()
Добавляем в ProgramsConfig.GetAllPrograms()

3. Liskov Substitution (Подстановка Лисков)
Все программы работают одинаково через BaseService:
MenuManager работает с любой программой через BaseService
Можно заменить одну программу на другую

4. Interface Segregation (Разделение интерфейсов)
BaseService требует только самое необходимое:
Name - название программы
Run() - запуск программы
Не заставляет программы делать то, что им не нужно

5. Dependency Inversion (Инверсия зависимостей)
MenuManager зависит от абстракции (BaseService), а не от конкретных программ

Что убрал:
Всю XML-документацию - слишком сложно для начинающих
Сложные структуры данных (ValidationResult, CalculationResult)
Избыточные константы и регионы (#region)
Перечисления (enum) - заменил на простые switch
Сложное форматирование - оставил базовое
Избыточные методы валидации - оставил только базовые

Что сохранил для обучения:
Наследование - BaseService как родитель для всех программ
Полиморфизм - MenuManager работает с любыми программами через BaseService
Абстрактные классы - BaseService как шаблон
Статические классы - ConsoleHelper, InputValidator
Принципы SOLID в упрощенном виде

Упрощения для понимания:
Более простые названия методов
Прямая обработка ошибок вместо сложных структур
Линейная логика без глубокой вложенности
Минимум "магических чисел" - все константы понятны
Наглядные примеры с комментариями в коде
